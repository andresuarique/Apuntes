### Test Unitarios

- **Definición**: Prueba de la unidad más pequeña de un sistema o aplicación, asegurando que cada módulo funcione correctamente de forma individual.
- **Objetivo**: Verificar que los componentes del programa, como nombres, tipos de datos y valores devueltos, sean correctos.
- **Realizados por**: Generalmente desarrolladores, pero también puede ser realizado por QA.

---

### Las tres A's del Unit Testing

1. **Arrange (Organizar)**: Definir los requisitos que debe cumplir el código.
2. **Act (Actuar)**: Realizar la llamada al código que se está probando.
3. **Assert (Afirmar)**: Verificar si los resultados obtenidos coinciden con los esperados.

---

### Principio F.I.R.S.T

- **Fast**: Las pruebas deben ejecutarse en pocos segundos.
- **Independent**: Cada prueba debe ser independiente, sin afectar los resultados de otras.
- **Repeatable**: El resultado debe ser consistente en cualquier entorno.
- **Self-validating**: El test debe proporcionar un resultado claro, indicando si pasó o no.
- **Timely**: Las pruebas deben desarrollarse lo antes posible, idealmente antes de subir el código a producción.
